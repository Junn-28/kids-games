# きおくバトル：ハンデに「コスト」を入れる

## 1. いま何が起きているか

`games/kioku/KiokuGame.jsx` のハンデは4つの独立したつまみです。

| つまみ | 範囲 | やさしくする向き |
|---|---|---|
| おぼえる かず `tiles` | 3〜16 | 減らす |
| みる じかん `peek` | 1.0〜9.0 びょう | 伸ばす |
| まちがえて いい かず `lives` | 0〜5 | 増やす |
| ことばの ながさ `wlen`（ことばモード） | 2〜5 もじ | 短くする |
| ぎゃく `rev` | on / off | off |

点数は `すすめた かず ÷ てじゅんの かず × 100` で、**ハンデに関係なく100点満点**。
これが「3さいと大人が同じ盤で勝負できる」というこのゲームの背骨です。

問題は、つまみ同士に何の関係もないこと。

- `LEVELS` を押した直後だけ「レベル3」と表示され、`➖➕` を1回でも触ると
  表示が **「じぶんで せってい」** になって、以後どんな設定も同じ扱いになる。
  16こ／9びょう／5かいミス可 も、14こ／2.5びょう／ミス不可 も、区別がない。
- 大人が「みる じかん」だけ 3.5 → 8.0 に伸ばしても、画面上は何も起きない。
- ひとりモードの最高記録 `best[mode]` は難易度を持たないので、
  レベル1で出した100点とレベル6で出した100点が同じ棚に並ぶ。

つまり **設定の空間に「ものさし」が無い**。コストの導入とは、この
ものさしを入れることです。

---

## 2. どのトレードオフ様式を採るか

難易度と報酬を釣り合わせる一般的なやり方は4つあります。

| 様式 | 中身 | このゲームでの評価 |
|---|---|---|
| **A. 予算型（point buy）** | 総量が決まっていて、配分だけ自由 | **採用。** 100点満点を壊さない |
| B. 倍率型（score multiplier） | 設定は自由、点数が難易度で伸縮 | **却下。**後述 |
| C. 競り型（auction） | 互いにハンデを提示し合う | こども向けの操作量を超える |
| D. 適応型（DDA） | 成績を見てゲームが自動調整 | 将来の追加候補。今回の要求とは別物 |

**Bを却下する理由**が設計の要です。倍率型にすると、レベル1のこどもは
どうがんばっても最大30点、レベル5の大人は最大100点になり、
「同じ盤で勝負になる」が即座に壊れます。今回いただいた
「子どもとも遊べる点は維持」という条件と真っ向からぶつかるので、
**点数には一切手を入れません**。

コストは **点数ではなく設定にかける**。これがこの設計の一行要約です。

## 3. むずかしさ（difficulty）の式

設定の組み合わせを1つの整数にします。

```js
/* おぼえる 1こ あたりの おもさ。モードで ちがう */
const ITEM  = { num: 10, kana: 12, word: 14 };
const DECOY = 4;                                    // にせものの たま 1こ
const LIFE_MUL = [1, 0.90, 0.82, 0.76, 0.72, 0.69]; // lives 0〜5
const REV_MUL  = 1.3;

function difficulty(p, mode) {
  const N = tilesOf(p, mode);                 // 盤に出る たまの ぜんぶ
  const L = mode === "word" ? p.wlen : N;     // じゅんばんを おぼえる かず
  const base = L * ITEM[mode] + (N - L) * DECOY;
  const time = 50 / (5 + p.peek);             // 1.0びょう→8.33  5.0→5.00  9.0→3.57
  return Math.round(base * time / 10 * LIFE_MUL[p.lives] * (p.rev ? REV_MUL : 1));
}
```

### なぜこの形か

**`ITEM` がモードで違う理由。** すうじモードは「1,2,3…」という順番がタダで
手に入るので、覚える負荷は位置だけ。あいうえおモードは50音の
どこから始まるかを思い出す分だけ重い。ことばモードは単語そのものと
その綴りを保持する必要があるので、いちばん重い。

**にせものの たまを別勘定にした理由。** ことばモードでは `tiles` のうち
`wlen` こだけが本物で、残りは順番を持たないノイズです。同じ重みで数えると、
にせものを増やすだけで難易度が上がることになってしまう。だから
本物 14 に対してにせもの 4 と、はっきり安くしています。

**時間を `50 / (5 + peek)` にした理由。** 引き算（`- peek × 定数`）だと、
たま4この盤で1秒伸ばすのも14この盤で1秒伸ばすのも同じ値引きになります。
実際には **1こあたり何秒あるか** が効くので、時間は掛け算の係数にしました。
`+5` は、9びょうでも係数が 3.57 で止まる（無限に楽にならない）ための下駄です。

**`lives` を掛け算にした理由。** 部分点方式なので、1回目のミスを許されると
そこで終わらずに続けられる＝価値が大きい。2回目以降は逓減する。
だから `[1, .90, .82, .76, .72, .69]` と間隔を詰めた等比もどきにしています。

**検証済み：** 3モードすべてで、`tiles↑`／`peek↓`／`lives↓`／`wlen↑` の
どれもが単調に難易度を上げます（反転する組み合わせはゼロ件）。

## 4. レベル＝線（要求値）

新しい定数表は作りません。**いまの `LEVELS` プリセットの難易度を、
そのままそのレベルの要求値にします。**

```js
const NEED = {};                                  // NEED[mode][lv]
for (const m of ["num", "kana", "word"])
  NEED[m] = LEVELS.map((L) => difficulty({ ...L, rev: false }, m));
```

こうすると、プリセットは定義上つねに自分の線をちょうど満たす（誤差0）。
表を二重管理しなくて済み、`LEVELS` をいじれば線も自動で追随します。

計算結果：

| | レベル1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 🔢 すうじ | 16 | 28 | 40 | 59 | 75 | 93 |
| 🔤 あいうえお | 20 | 34 | 48 | 71 | 90 | 112 |
| 💭 ことば | 15 | 26 | 31 | 47 | 55 | 71 |

**レベル0＝「れんしゅう」を足します。** 要求値は 0、つまり無制限。
3さいの子に「たま3こ・9びょう・5回ミス可」で遊ばせたいときの逃げ道です
（この設定の難易度は 7〜9 で、レベル1の線に届きません）。
ここを塞ぐと「こどもとも遊べる」が壊れるので、必ず残します。

## 5. コストのかけかた：自動おぎない

**推奨案。** つまみを楽な方向に動かしたとき、**別のつまみが自動で
きつくなって線を保つ**。動いた側をその場で光らせて見せます。

```
みる じかん  ➖  [ 3.5 びょう ]  ➕     ← 押す
                 ↓
みる じかん  ➖  [ 4.5 びょう ]  ➕
おぼえる かず ➖  [   12 こ   ]  ➕     ← 10 から自動で増えて光る
             「じかんを のばしたぶん、たまが 2こ ふえたよ」
```

おぎなう順番（触っていないつまみから、影響の分かりやすい順）：

| 動かしたもの | おぎなう先（上から順に試す） |
|---|---|
| `peek` を伸ばした | `tiles` を増やす → `peek` を戻す（＝拒否） |
| `tiles` を減らした | `peek` を縮める → `lives` を減らす → 拒否 |
| `lives` を増やした | `tiles` を増やす → `peek` を縮める → 拒否 |
| `wlen` を減らした | `tiles`（にせもの）を増やす → `peek` を縮める → 拒否 |

上限に当たって埋め合わせられないときは、その `➕`／`➖` を
`disabled` にします（`Stepper` の `canInc`/`canDec` がすでにあるので、
そこに条件を足すだけ）。**きつくする方向は常に自由**です。線より上に
出るのは構わない（メーターに余り分として出す）。

もっとやさしくしたければ、**レベルを下げる**。これは番号が変わるので、
一緒に遊んでいる相手から必ず見えます。これが唯一の「安くする」経路です。

### 代替案（かたい版）

自動で数字が動くのを避けたいなら、`➕` を無効にして
「レベル4には たまが 12こ いるよ」と理由だけ出す形もあります。
**自動おぎないを推す理由**は、こどもが触ったときに
「押したのに何も起きない」より「別の数字が動く」ほうが、
トレードオフそのものを目で学べるからです。ここは好みなので、
実装前に決めてください。

## 6. 画面

### したく画面：`PlayerSetup` のレベル行を置き換える

いまの 1〜6 のボタン列を、**目盛りつきメーター**にします。

```
┌────────────────────────────────────────┐
│  むずかしさ                    レベル4  │
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░         │
│  れ    1    2    3    ▲    5    6      │
└────────────────────────────────────────┘
```

- 目盛り（れんしゅう・1〜6）は**そのまま押せるボタン**。
  押すとプリセットに飛ぶ＝いまのレベルボタンと同じ操作なので、
  こどもが覚え直すことはありません。
- 塗りは現在の難易度。線より上に出た分は色を変えて「おまけ」として見せる。
- つまみを動かすと塗りがその場で動く。ここが「コストが見える」場所です。

数字（59 など）は大人向けに小さく添える程度に留めます。
こどもが読むのは **塗りの長さと、いま立っている目盛り** だけで足ります。

### そのほか

- **`ready` 画面**：`{myTiles}こ ／ {peek}びょう` の行に `レベル4` を足す。
- **`final` 画面**：名前の横にレベルを出す。
  `🧒 レベル1 ／ 🧑 レベル5` と並ぶと、結果が正直に読めるようになります。
- **`home` のコツ欄**：文面を「レベルの線を保ったまま、じかんと かずを
  交換できる」という説明に差し替え。

## 7. セーブ形式

### レベルは保存しない（実装時に変えた点）

当初は `p[i].lv` を保存する設計にしていましたが、**保存せず毎回導出する**形に
変えました。`levelOf(p, mode)` ＝ いまの設定が満たしている最大の線、です。

保存をやめると、面倒がまとめて消えます。

- **セーブ形式が変わらない。** 移行も既定値も要らない。
- **モードを跨いでも破綻しない。** 保存すると「目標はレベル4だが、
  ことばモードでは線に届いていない」という*目標と実績の二重*状態が生まれ、
  どちらを画面に出すか決めねばならなくなる。導出なら数は常に1つ。
- **床が自動で決まる。** 制約は「**いま立っている目盛りより下げられない**」の
  一言になり、`levelOf` の定義からこれは常に満たせる。れんしゅう（0）は
  要求値0なので、無制限がそのまま落ちてくる。

代償は「いま届いていないレベルを目標に据える」ができないこと。ですが目盛りを
叩けば一発で飛べるので、実用上は要りませんでした。

**`best` の差し替えは予定どおり。** いまの `{ num, word, kana }` は難易度を
持たないので、`best[mode][lv]` の形（レベルごとの棚）にします。
古い形式（数値）は配列ではないので `safeNum` を通らずゼロに戻るだけで、
移行コードは要りません。**記録が1回だけ消えます。**

## 9. 限界と、把握しておくこと

**高いレベルでは「みる じかん」の可動域が狭い。** レベル6ですうじなら
3びょうまで、5びょうにはできません。`tiles` の上限16は、`SIZES` の
いちばん小さい たま（幅320pxの盤で56px）が押せる限界から来ているので、
ここは動かさない前提です。

逃げ道は用意されています。**`🔁 ぎゃく` を on にすると ×1.3** ぶんの
余裕が生まれるので、「ぎゃくにする代わりに2びょうもらう」という
交換が成立します。ぎゃくが単なる追い討ちではなく通貨になる、というのは
この設計の副産物として気に入っている点です。

**ことばモードのレベル2と3が近い**（26 と 31）。もとの `LEVELS` で
L2とL3がどちらも `wlen: 3` を共有しているためです。気になるなら
`LEVELS[2].wlen` を 3→4 にすると 31→42 に開きますが、
**5さいに4もじは早い**ので、現状維持を勧めます。

**コストは不正防止ではありません。** 「れんしゅう」を選べば誰でも
好き放題にできます。狙いは、設定に共通のものさしを与えて、
交換していることを本人と相手に見せることです。家族で遊ぶゲームなので、
これで十分だと考えています。

## 10. 実装結果

`games/kioku/KiokuGame.jsx` に入っています。追加した部品は

| もの | 役割 |
|---|---|
| `difficulty(p, mode)` | 設定 → むずかしさの整数 |
| `NEED[mode][lv]` | 目盛りの位置。`LEVELS` から自動生成 |
| `levelOf(p, mode)` | いま立っている目盛り |
| `tighten(p, dial)` | つまみを1段きつくする |
| `compensate(p, mode, patch, order)` | 動かした結果。おぎないきれなければ `null` |
| `meterPos(d, mode)` | むずかしさ → メーターの位置（0〜1） |
| `<Meter>` | 目盛り付きメーター。目盛りがそのままプリセットボタン |
| `PRACTICE` | レベル0 の設定（3こ・7びょう・3かいミス可） |

`Stepper` は `flash` を受け取るようになり、自動で動いた側の数字が光ります。

### 確かめたこと

**ロジック**：設定 34,272 通り × 3モードを総当たりし、245,256 回の操作すべてで

- むずかしさが全つまみに対して単調（逆転ゼロ件）
- **立っている目盛りを一度も割らない**（コストの中核。全件成立）
- 押したつまみが必ず希望どおりになる（おぎないは別のつまみだけを動かす）
- `order` に無いつまみが勝手に動かない／範囲外に出ない
- れんしゅう（0）では一度も拒否されず、おぎないも入らない
- メーターの塗りが各目盛りにぴったり一致する

**実機**（headless Chrome を CDP で操作）：

- レベル4で `みる じかん ➕` → `おぼえる かず` が自動で増え、レベル4を維持。
  3.5びょう/10こ → 5.5びょう/13こ → 8.5びょう/16こ で `➕` が無効化。
  §8 の表の予測どおり。
- 逆向きも成立：`おぼえる かず ➖` → `みる じかん` が自動で縮む。
- 🌱 れんしゅうでは時間を伸ばしても何も起きない（＝制約なし）。
- ことばモードで単語を短くしても線を割らない（にせものの たまが肩代わり）。
- こども🌱で100点、おとなレベル6で7点 → **こどもの勝ち**。
  結果表に両者のレベルが並ぶ。100点満点の対等さは無傷。
- 設定画面を乱打（ステッパー60回＋全目盛り＋モード／人数／回数切替）しても
  console の error / warning / exception はゼロ。
